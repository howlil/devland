# Documentation Policy

`Required` rules need explicit rationale and evidence to deviate. `Defaults` may be overridden when project evidence supports a better choice.

## Required

- Update documentation or canonical state in the same logical change when a contract it describes changes.
- Keep public product documentation separate from speculative or internal work artifacts when the repository defines that audience boundary.

## Defaults

- Do not maintain speculative documentation for behavior that does not exist.
- Avoid maintaining the same canonical project fact independently in multiple agent-specific files.
- Prefer references to a source of truth over copied prose when duplication would create drift.
