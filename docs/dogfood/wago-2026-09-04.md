# Wago external dogfood — 2026-09-04

## Decision

**Production-readiness classification: `ready-with-known-limits`.**

Devland completed a real external-repository bootstrap and exercised the read-only MCP feedback surface against Wago. The exercise found and closed material setup/feedback-loop gaps without expanding Devland into a repository client, execution agent, CI/CD system, or analytics backend.

This result does **not** claim complete production/outcome observability for Wago. Wago does not yet have a normalized Devland engineering-event spool, so delivery and outcome metrics remain empty rather than inferred from GitHub history.

## External repository

Repository: `howlil/wago`

Wago is a TypeScript monorepo with gateway, dashboard, and documentation applications, risk-routed CI, Docker/release boundaries, SQLite persistence, and explicit authentication/security constraints. Existing `.agents/*` files remain Wago's authoritative product, architecture, quality, decision, and current-iteration knowledge.

The Devland bootstrap intentionally added only supplemental machine-readable facts:

- `.devland/project.yaml` — project identity, stack, architecture reference, production environment, qualities, and one authority constraint;
- `.devland/state.yaml` — empty lightweight coordination state;
- a short `AGENTS.md` routing note preserving `.agents/*` authority;
- `.devland/**` excluded from Wago's normal application CI path after the bootstrap change.

No Wago runtime or product behavior changed.

## Read-only MCP evidence

The external gate checked out Devland `master` separately from Wago and exercised the actual MCP server.

Confirmed:

- MCP registry is exactly `resolve_context`, `doctor`, `flow_report`;
- Wago canonical Devland context validates;
- the three retrospective risk-lane cases resolve as expected;
- `doctor` runs from caller-supplied repository evidence without Devland fetching repository files;
- `flow_report` with no supplied events returns valid empty evidence (`event_count: 0`, `evidence_status: empty`) instead of fabricating delivery or value data.

The temporary dogfood CI job/workflow was removed after evidence was collected. Wago does not carry a permanent Devland test ceremony solely for this milestone.

## Findings

### Blocker — M6 feedback surface did not exist

**Observed:** the M7 plan assumed `resolve_context + doctor + flow_report`, but live Devland `master` initially exposed only `resolve_context`.

**Resolution:** closed before external dogfood in Devland PR #71. The MCP server now exposes exactly three read-only tools and reuses core `doctorProject` / `flowReport` semantics through transient caller-supplied evidence.

**Status:** fixed now.

### High friction — stateless MCP cannot inspect a repository implicitly

**Observed:** the deployed MCP service has no external repository filesystem and must not acquire GitHub/filesystem ownership merely to implement `doctor` or `flow_report`.

**Resolution:** surrounding runtimes supply canonical YAML plus a transient repository snapshot or normalized event NDJSON. Devland stages that evidence in an isolated temporary project, delegates to the same core logic, then removes it.

**Status:** fixed now.

### High friction — Devland source checkout nested inside a pnpm workspace

**Observed:** the first Wago dogfood run checked Devland out under Wago and executed `pnpm --dir`. pnpm bound to Wago's parent workspace, so Devland runtime dependencies were not installed at the expected module boundary and `devland validate` failed with a missing `ajv` package.

**Resolution for dogfood:** isolate the Devland source checkout outside the Wago workspace (`RUNNER_TEMP`) before installation. Canonical validation and the complete MCP feedback loop then passed.

**Classification:** after-feedback. This is source-checkout/bootstrap friction, not a semantic blocker for the packaged/container path. Do not add a new package subsystem solely from one observation.

### High friction — `.devland/**` would pay Wago's full core CI gate

**Observed:** Wago's normal CI ignored `.agents/**` but not `.devland/**`, so metadata-only maintenance would unnecessarily run application lint/tests/build.

**Resolution:** Wago bootstrap adds `.devland/**` to the normal core CI `paths-ignore`. The workflow edit itself paid the normal integration/security gates once.

**Status:** fixed in Wago PR #124.

### Limitation — doctor stack discovery is shallow for monorepo TypeScript layouts

**Observed:** current repository-fact discovery focuses on a small set of root-level source/package patterns. Wago's primary TypeScript implementation lives under `apps/**`, so doctor does not provide comprehensive stack evidence for that topology.

**Classification:** after-feedback, non-blocking. Existing doctor behavior remains deterministic and honest; expanding scanner breadth requires additional external evidence that it changes decisions enough to justify maintenance cost.

### Evidence gap — no Wago normalized delivery/outcome event spool

**Observed:** Wago currently supplies no `devland.event/v1` history for work → change → merge → deployment → outcome reconstruction.

**Result:** `flow_report` correctly reports empty evidence. No `idea_to_production`, `production_to_outcome`, `idea_to_outcome`, correlation coverage, or outcome coverage values are claimed for Wago.

**Classification:** known limit. Populate evidence only when the surrounding runtime has a real collection path; do not backfill guessed metrics from commit history.

## Production-readiness interpretation

Devland is **ready-with-known-limits** for the validated primary journey:

```text
external repository
→ minimal canonical bootstrap
→ resolve risk-budgeted context
→ read deterministic doctor feedback from supplied evidence
→ read flow/outcome feedback from supplied normalized events
→ external runtime owns repository/test/Git/CI/deploy actions
```

The read-only semantic-control-plane boundary held during dogfood. The milestone did not justify a dashboard, task database, GitHub client, test runner, deployment controller, telemetry collector, or additional MCP tools.

Before calling Devland fully `ready`, gather real normalized delivery/outcome events from at least one external repository and observe whether flow metrics materially change subsequent engineering decisions. Until then, event-driven FAST + VALUE feedback is implemented and transport-verified, but not yet externally populated end-to-end.
